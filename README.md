# ImageViewer

Windows 用の軽量な画像ビューア（C# / .NET 10 / WPF）。
**ビューア専用**で、画像ファイルには一切書き込まない方針。

## 必要なもの

- 開発：Visual Studio 2026（.NET 10 SDK 入り）
  - ワークロード「.NET デスクトップ開発」
- 実行：.NET 10 Desktop Runtime（framework-dependent の軽量exeなので）

`ImageViewer.sln` を開いて F5 で起動できる。
exe は x64 固定（同梱する libwebp.dll に合わせている）。

テストは「テスト エクスプローラー」から実行する（MSTest）。

## WebP 対応（二段構え）

1. アニメーションWebP は libwebpdemux.dll で読む
2. 静止画は、まず WIC で読む（OS に「WebP 画像拡張機能」があればここで読める）
3. 読めなかったら libwebp.dll で読む

必要な DLL は `native/x64/` に入れてリポジトリに含めている。clone してそのままビルド・実行できる。
ビルド時に出力フォルダへコピーされる（csproj が `native/x64/*.dll` を全部コピーする）。

### 同梱している DLL（3つセット）

| DLL | 役割 | 依存先 |
|---|---|---|
| `libwebp.dll` | WebP のデコード本体 | `libsharpyuv.dll` |
| `libwebpdemux.dll` | アニメーションWebP のコマ取り出し | `libwebp.dll` |
| `libsharpyuv.dll` | 色変換（libwebp が内部で使う） | なし |

**3つとも必要。** 入れ替えや削除をするときは、必ず3つまとめて扱う。
1つでも欠けると、依存している DLL が連鎖して読み込めなくなる。
たとえば `libsharpyuv.dll` が無いと `libwebp.dll` が読めず、それに依存する `libwebpdemux.dll` も読めない。
このときエラーは出ず、DLL が無いときと同じ動き（静止画は WIC だけ、アニメーションWebP は1コマ目だけ静止画）になる。
そのかわり、起動時に3つとも読めるか調べて、読めなければステータスバーに「⚠ WebP DLL 不足：libsharpyuv.dll」のように出す
（マウスを乗せると、詳しい理由：無い DLL・64 ビット版でない・Visual C++ ランタイムが無い、など）。

どれも x64 版（exe が x64 固定なので）。実行には Visual C++ 再頒布可能パッケージ（`VCRUNTIME140.dll`）も必要だが、たいていの PC には入っている。

DLL が無くてもビルド・実行はできるので、外して使うこともできる（そのときは上の 2. だけで動く）。

### ライセンス

libwebp は BSD ライセンス。DLL を含めて配布するときは、ライセンス文（libwebp の `COPYING`）も一緒に入れること。
`native/x64/COPYING` に置いてあり、ビルド時に出力フォルダへ `libwebp-COPYING.txt` という名前でコピーされる。

### DLL を更新・入れ替えるとき（vcpkg の例）

```
vcpkg install libwebp:x64-windows
```

`installed\x64-windows\bin\` にある上の3つを、まとめて `native/x64/` に上書きコピーして、コミットし直す。

## HEIC / AVIF / JPEG XL

`.heic` / `.heif` / `.hif` / `.avif` / `.jxl` もフォルダの一覧に入れて、WIC で読む。

- OS にコーデック（Microsoft Store の「HEIF 画像拡張機能」「AV1 Video Extension」など）が入っていれば表示できる
- 入っていなければ「表示できません」と出し、拡張機能が必要なことも添える（一覧では「×」）
- EXIF の向きはコーデック側で反映される前提で、自分では回さない
- 情報パネルは「ファイル」の欄だけ（EXIF を自前で読めないので）

## アニメーション（GIF / WebP）

開いたら自動で再生する。

- GIF：WIC でコマを取り出し、メタデータ（位置・表示時間・Disposal・ループ回数）に従って自前で合成する
  - Disposal 2（背景に戻す）はブラウザに合わせて透明にする
  - ループ回数は Chrome / Firefox と同じ解釈（拡張なし = 1回、0 = 無限、N = N+1回）
- WebP：libwebpdemux（WebPAnimDecoder）が合成済みのコマを返すので、それをそのまま使う
- 表示時間が 10ms 以下のコマは 100ms として扱う（ブラウザと同じ）
- 決められた回数を再生したら最後のコマで止まる（P で最初から再生し直す）
- 処理が遅れたときはコマを飛ばして追いつく。最小化している間は止める
- 全コマを合成済みでメモリに持つ。上限（ini の `AnimationMaxMB`、既定 256MB）を超えるものは1コマ目だけ表示して、ステータスバーに「アニメ省略」と出す
- ズーム・パン・回転は再生中もそのまま効く
- ステータスバーに「コマ 3 / 20」と出す（一時停止中・再生終了も表示）

## 起動（ウィンドウは1つ）

起動中にもう一度起動したら（ファイルの関連付け・exe へのドロップなど）、新しいウィンドウは出さずに、起動中のウィンドウで開いて前に出す。
新しいプロセスはパスを渡したらすぐ終わるので、2回目からは速く開く。

- パスなしで起動したら（スタートメニューなど）、起動中のウィンドウを前に出すだけ
- 最小化していたら元に戻す（最大化していたなら最大化に戻る）
- ダイアログ（フォルダの端・ファイルを開く）を出している間に来たら、閉じてから開く
- exe の場所ごとに1つ（開発中のビルドと、普段使いの exe は別々に動く。ini も exe ごと）
- パスは名前付きパイプで渡す。同じユーザーの起動からしか受け付けない
- 起動中のアプリが固まっていてパスを渡せない（3 秒待っても応答が無い）ときは、ふつうに新しいウィンドウで開く
- ini の `[Startup] SingleInstance=false` で、起動するたびに別のウィンドウにできる

## 設定の保存

exe と同じフォルダの `ImageViewer.ini` に、終了時に保存して次の起動で読み込む（UTF-8）。

```ini
[Window]
Left=100
Top=80
Width=1280
Height=800
Maximized=false

[Sort]
Key=Name
Descending=false

[Memory]
AnimationMaxMB=256
PrefetchMaxMB=512
ThumbnailMaxMB=256

[Thumbnail]
Size=160

[Slideshow]
IntervalSeconds=5

[InfoPanel]
Width=300

[View]
Background=Default

[Startup]
SingleInstance=true
```

- `[Window]`：通常時のウィンドウ位置とサイズ（物理ピクセル）と、最大化していたか
  - 最大化・全画面で終了しても、元に戻したときの位置とサイズを保存する。全画面は次回は通常表示で開く（全画面の前に最大化していたら最大化）
  - 保存した位置が画面外（モニタを外した等）なら、OS が画面内に収める
  - モニタごとに拡大率（DPI）が違っても、保存したときと同じ大きさで戻す（違う DPI のモニタへ移ると WPF が大きさを変えてしまうので、移った後にもう一度当て直している）
- `[Sort]`：並び順（`Name` / `LastWriteTime` / `Size`）と降順か
- `[Memory]`：メモリの上限（MB、1〜65536）。アプリに設定画面は無いので、ここを手で書き換える
  - `AnimationMaxMB`：アニメーション1枚に使うメモリ。超えたら1コマ目だけ表示
  - `PrefetchMaxMB`：先読みした画像の合計（表示中の画像は含まない）
  - `ThumbnailMaxMB`：サムネイルの合計。超えたら長く使っていないものから捨てる
  - 次の起動から効く。アプリを起動したまま書き換えても、終了時に消されない（この3つはファイル側の値を残す）
- `[Thumbnail]`：サムネイル一覧の大きさ（`64` / `80` / `96` / `128` / `160` / `192` / `224` / `256`）。Ctrl+ホイールで変えたものを保存する。ほかの値を書くと一番近いものになる
- `[InfoPanel]`：情報パネルの幅（200〜1200）。境目をドラッグして変えたものを保存する
- `[Slideshow]`：スライドショーで静止画1枚を出す秒数（0.5〜3600、小数も可）。アプリに設定画面は無いので、ここを手で書き換える
  - スライドショーを始めるたびに読み直すので、起動中に書き換えても次のスライドショーから効く。終了時にも消されない
- `[View]`：画像の後ろ（透明な部分）に敷くもの（`Default`：何も敷かない / `Checker`：市松模様 / `White`：白）。B で切り替えたものを保存する
- `[Startup]`：`SingleInstance` を `false` にすると、起動するたびに別のウィンドウで開く（2つのウィンドウで見比べたいときなど。下の「起動」）。アプリに設定画面は無いので、ここを手で書き換える。次の起動から効き、終了時にも消されない
- ファイルが無い・値が壊れているときは、その項目だけ既定値を使う。手で書くときは `true/false` の代わりに `1/0` でもいい
- exe の場所に書き込めないと保存されない（起動・終了はふつうにできる）。開発中は `bin\Debug\net10.0-windows\` にできる

## EXIF の向き

JPEG / TIFF は EXIF の Orientation を見て、撮影したときの向きで表示する（スマホの縦写真など）。
ファイルは書き換えない。縦横ピクセル数も向きを直した後の値を出す。
R / L での回転は、その上にさらに表示だけ回す。

## サムネイル一覧

フォルダを開くと一覧から始まる（ファイルを開いたときは、その画像を1枚表示）。T で「1枚表示 ⇔ 一覧」を切り替える。

- 矢印・PageUp / PageDown・Home / End で選ぶ。Enter / T / ダブルクリックで、選んだ画像を1枚表示で開く
- Esc で、一覧に入る前の画像に戻る（ズーム・回転もそのまま）。一覧から始めたときは戻る先が無いので何もしない
- 選ぶだけでは画像は読まない。ステータスバーのファイル名と「何枚目か」だけ変わる
- Ctrl+ホイールで大きさを変える（64〜256、8段階）。作り直しは起きない（下の「作り方」）
- 並び順は1枚表示と同じ。ツールバーで変えると一覧も並び替わる
- 読めない画像は「×」の印を出す。一覧自体は止まらない
- 一覧を出している間は、アニメーションは止めておく

サムネイルの作り方：

- 見えている行と、その上下1行だけ作る。同時に作るのは CPU のコア数の半分（2〜4枚）まで。スクロールで見えなくなったものは、待っている途中ならキャンセルする
- いつも最大の大きさ（256、高DPIなら DPI 倍。上限 512 ピクセル）で作って、表示のときに縮める。だから大きさを変えても作り直さない
- WIC にデコード時に縮小させる（JPEG は縮小しながら読むので速い）。EXIF の向きは1枚表示と同じように反映する
- アニメーション（GIF / WebP）は1コマ目だけ。ICO は一番大きいアイコンを使う。WebP は WIC で読めなければ libwebp で読む
- メモリに持つだけで、ディスクには保存しない（画像のフォルダに何も書かない方針なので）
- フォルダを開き直したら、ファイルの更新日時とサイズを見直して、変わっていたものだけ作り直す

## 画像の情報（EXIF）

I かツールバーのボタンで、右側に情報パネルを出す / 隠す。起動したときはいつも隠れている（開閉は保存しない）。

- 1枚表示では表示中の画像、一覧では選択中の画像の情報を出す。選択を動かすと追いかけて変わる
- 出す項目（値が無い項目・おかしな値は行ごと出さない。EXIF が無ければ「ファイル」だけ）
  - ファイル：ファイル名・形式・ピクセル数・ファイルサイズ・更新日時
  - 撮影：撮影日時・メーカー・機種・レンズ・焦点距離（35mm 換算）・F値・シャッター速度・ISO感度・露出補正・露出モード・測光方式・フラッシュ・ホワイトバランス
  - 位置情報：緯度・経度（度分秒と10進）・高度
  - その他：向き・ソフトウェア・作者・著作権
- ピクセル数は、ステータスバーと同じく向きを直した後の値（JPEG / TIFF）
- 右クリック →「情報をコピー」で、出ている情報をテキストでコピーできる
- パネルの左の境目をドラッグすると幅を変えられる（200〜1200。ini に保存する）

### 生成情報（画像生成AIのプロンプトなど）

Stable Diffusion WebUI（AUTOMATIC1111 / Forge など）が画像に書き込んだ生成情報を、「生成情報」の欄に出す。

- 読む場所：PNG はテキストチャンク `parameters`、JPEG / WebP は EXIF の UserComment
- プロンプト・ネガティブプロンプト（どちらも全文）と、設定の行（ステップ数・サンプラー・CFG スケール・シード・サイズ・モデルなど。知らない項目は WebUI の書き方のまま）
- 右クリック →「プロンプトをコピー」「ネガティブプロンプトをコピー」で、そのまま WebUI に貼れる
- JPEG / WebP の UserComment は、最後に「Steps: …」の設定の行があるときだけ生成情報とみなす（カメラのふつうのコメントと間違えないように）。それ以外は「その他」に「コメント」として出す
- PNG のほかのテキスト（`Software` など。ComfyUI の `prompt` / `workflow` も）は「PNG テキスト」の欄にそのまま出す。2000 文字を超えるものは省略する
- PNG のテキストは tEXt / zTXt / iTXt（圧縮も）を読む。画像データの後ろに置いてあっても読む
- EXIF は自前で読む（JPEG の APP1、TIFF、PNG の eXIf、WebP の EXIF チャンク）。HEIC などは「ファイル」の欄だけ
- 読むのはヘッダとメタデータだけで、画像はデコードしない。裏のスレッドで読むので、表示は待たせない
- 壊れた EXIF（範囲外のオフセット・ループする IFD・ありえない個数など）でも止まらず、読めた分だけ出す
- 書き込みは一切しない

## スライドショー

S かツールバーのボタンで、今の画像から始める / 止める。一覧からなら、選択中の画像を開いて始める。

- 静止画は ini の `IntervalSeconds`（既定 5 秒）ごとに次へ
- アニメーション（GIF / WebP）は、`IntervalSeconds` が過ぎてから1周し終わったところで次へ
  - 短いアニメーションは、時間になるまで繰り返す（再生回数が決まっていて途中で止まるものも、最初から再生し直す）
  - 1周が `IntervalSeconds` より長いものは、1周したら次へ（途中で切らない）
  - P で一時停止している間は待つ
- 最後の画像の次は先頭に戻って、止めるまでずっと続ける（最後の画像を出している間に、先頭も先読みしておく）
- 時間は画像が出てから数える。読み込みに時間がかかっても、表示時間は削られない
- 読めない画像はエラーを出したまま、同じ時間が経ったら次へ
- ← → などで手で送ってもいい。送った画像から数え直す
- 止めるのは S / Esc / ツールバーのボタン。別のファイル・フォルダを開いたとき、一覧（T）に切り替えたときも止まる
- 全画面にはしない（全画面にしたいときは Enter）。全画面中の Esc は、まずスライドショーを止めて、もう一度押すと全画面も終わる
- 最小化している間は送らない
- スライドショー中は、ステータスバーに「スライドショー 5秒」と出す（全画面中はステータスバーごと隠れる）

## フォルダの移動

フォルダを順番にたどって移る。サブフォルダの中にも入る。

```
（開いたフォルダの親）
  A\          1
    A1\       2   フォルダの次は、その中のサブフォルダ
      A1x\    3   さらに奥まで全部
    A2\       4
  B\          5   最後のサブフォルダの次は、元の階層の次のフォルダ
```

- 「前」はこの順番をそのまま逆にたどる（B の前は A2、A1 の前は A）
- たどる範囲は、ファイル・フォルダを開いたときのそのフォルダの親まで。そこから上には行かない（ドライブ全体をたどらないように）。隣のフォルダへ移っても範囲は変わらない

- ↓ で次のフォルダの先頭の画像、↑ で前のフォルダの最後の画像を出す（一覧では Ctrl+↓ / Ctrl+↑。一覧のまま中身が入れ替わる）
- フォルダの最後の画像で「次へ」（→ / PageDown / Space / ホイール下）とすると、ダイアログで聞く
  - 「次のフォルダへ」：次のフォルダの先頭の画像を出す
  - 「フォルダの先頭に戻る」：同じフォルダの先頭に戻る
  - 「キャンセル」（Esc）：何もしない
- フォルダの最初の画像で「前へ」とすると、同じように「前のフォルダへ」（前のフォルダの最後の画像）/「フォルダの最後に戻る」/「キャンセル」
- 同じ階層の中の順番は、フォルダ名の自然順（ファイルの並び順の設定とは関係なく、いつも名前の昇順）
- 表示できる画像が無いフォルダは飛ばす（その中のサブフォルダには入る）。隠しフォルダ・システムフォルダ（`$RECYCLE.BIN` など）、ジャンクション・シンボリックリンクには入らない（ループしないように）
- 範囲の最後のフォルダより先は無い（反対の端には回らない）。↑↓ のときは画面下に「次のフォルダはありません」と出し、ダイアログでは「次のフォルダへ」が押せなくなる
- 移ったら、画面下にフォルダ名（範囲の一番上からの相対パス。「A\A1」など）を数秒出す（全画面でも見えるように）
- キーを押しっぱなしで端に来たとき・ホイールを回し続けたときは、ダイアログを出さない（出た瞬間にボタンが押されないように）。押し直すと出る
- スライドショー中に別のフォルダへ移ったら、スライドショーは止まる（スライドショー自体は、フォルダの最後から先頭に戻って続ける）
- 隣のフォルダは裏で探すので、ネットワークドライブなどで遅くても画面は止まらない

## フォルダの見張り

開いているフォルダで画像が増えた・消えた・名前が変わったら、一覧に反映する（画像生成AIの出力フォルダを開きっぱなしにしておく、など）。

- 1枚表示で、並び順の最後の画像を見ていたら、増えた画像（新しい最後の画像）へ移る。途中の画像を見ているときは、一覧と「何枚目か」が変わるだけ
  - スライドショー中は移らない（スライドショーがそのうちたどり着く）
  - 「最後」は並び順での最後。更新日時の降順で並べていると、新しい画像は先頭に入るので移らない
- 見ている画像が消された・移動されたら、表示したまま残す。別の画像へ移ったら一覧から外れる
- サムネイル一覧にも反映する。選んでいた画像が消されたら、同じ位置の画像を選ぶ（一覧は選択している画像の位置までスクロールし直す）
- 書き込みの途中で読まないよう、変化が 0.5 秒止まってから反映する（書き込みが続いても 3 秒で反映する）
- 見るのは開いているフォルダだけ（サブフォルダは見ない）。見張れないフォルダ（ネットワークドライブの一部など）では、反映しないだけ
- 同じ名前のまま上書きされた画像は、読み直さない（画像もサムネイルも、ファイル・フォルダを開き直すと読み直す）

## エクスプローラーで開く

E かツールバーのボタンで、表示中の画像（一覧なら選択中の画像）があるフォルダをエクスプローラーで開き、その画像を選んだ状態にする。

- このビューアでは編集・削除・移動をしないので、ファイルを操作したいときはここからエクスプローラーで
- 同じフォルダのエクスプローラーが開いていれば、それを使って画像を選び直す
- 画像が消されていたらフォルダだけ開く。フォルダも無ければ、画面下に「ファイルが見つかりませんでした」と出す

## 画面構成

- 上部：ツールバー（左回転 / 右回転 / 全画面 / 一覧 ⇔ 1枚表示 / 情報パネル / スライドショー / エクスプローラーで開く / 並び順 / 昇順・降順）
- 中央：画像表示領域（情報パネルを開くと、右に幅 300 のパネルが出て、その分だけ狭くなる）
- 下部：ステータスバー（ファイル名 / 何枚目か / 縦横ピクセル数 / 表示倍率）
  - 次の画像を読み込んでいる間は、縦横ピクセル数の欄に「読み込み中…」と出す
  - ファイルを開いてフォルダの一覧を作っている間は、何枚目かの欄に「… / …」と出す
- タイトルバーには「ファイル名 - ImageViewer」だけ出す
- 全画面中はツールバーとステータスバーを隠す
- 一覧を出している間は、縦横ピクセル数の欄は空にして、倍率の欄にサムネイルの大きさ（「160px」など）を出す

## 並び順

- 名前（自然順） / 更新日時 / サイズ をツールバーのボタンで選ぶ（選択中のボタンはハイライト＋太字）
- 昇順・降順はその隣のボタンで切り替え（今の状態をアイコンと文字で表示）
- 主キーが同じものは名前の自然順で並べる
- 更新日時・サイズは、ファイルごとに問い合わせずに、フォルダを1回列挙して一緒に取る（ネットワークドライブで速い）
- 切り替えても表示中の画像はそのまま（読み直さない）。一覧の順番と「何枚目か」だけ変わる
- フォルダを開いたときは、サムネイル一覧で先頭（並び順の1枚目）を選んだ状態にする

## 大きい画像（画面に合わせて縮めて読む）

モニタよりずっと大きい静止画は、モニタの大きさまで縮めながら読む。メモリもデコード時間も減る（JPEG は縮めながら読めるので特に速い）。

- 縮める大きさは、ウィンドウがあるモニタの長い辺（物理ピクセル）。ウィンドウに収めた表示は、これで足りる
- 長い辺がその 1.25 倍を超えるときだけ縮める（少ししか縮まないなら、そのまま読む）
- 拡大して（または大きいモニタへ移して）縮めた画像では足りなくなったら、元の大きさで読み直して差し替える。読み直している間は、縮めた画像を引き伸ばして出しておく。ズーム・位置・回転はそのまま
- ステータスバーの縦横ピクセル数は、縮めて読んでも元の大きさを出す
- 縮めるのは WIC で読む静止画だけ。アニメーション（GIF / WebP）・ICO・libwebp で読む WebP は縮めない
- 先読みした画像も縮めて持つので、`PrefetchMaxMB` に入る枚数が増える

## 先読み

表示中の画像の前後を裏でデコードしておき、送りを速くする。

- ファイルを開いたときは、その画像をすぐ読み始める。同じフォルダの一覧（列挙と並べ替え）は裏で作るので、ファイル数の多いフォルダやネットワークドライブでも表示は待たない
  - 一覧ができるまでは、ステータスバーの「何枚目か」は「… / …」。前後の移動・一覧（T）・スライドショーは、一覧ができてから効く（ズーム・回転などはすぐ使える）
  - 一覧ができたら、前後の先読みを始める

- 進んでいる方向に2枚、逆方向に1枚（現在の画像と合わせて最大4枚をメモリに持つ）
- 表示する画像のデコードが最優先。先読みは同時に1枚ずつ
- 先読みが終わっている画像は、そのまま表示に使う（読み込み途中なら、その完了を待つ）
- 順番待ちの先読みが表示対象になったら、待たずにすぐ読む
- 範囲外になった画像はキャッシュから捨てる
- 先読みした画像の合計がメモリ上限（ini の `PrefetchMaxMB`、既定 512MB）を超えそうなら、優先度の低いものから諦める（目安。読み込み中の画像は大きさが分からないので、少し超えることはある）
- 同じ画像を開き直すと読み直す（ファイルの更新を反映するため）
